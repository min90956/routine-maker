# 주간 헬스 & 러닝 스마트 루틴 메이커 (날씨 API 버전)

운동 불가 요일, 목표 횟수, 지난주 부위별 강도를 입력하면 **다음 주(월~일)** 헬스·러닝 루틴을 짜 주는 데스크톱(tkinter) 프로그램입니다.
이번 업데이트에서 **Open-Meteo 날씨 API**를 붙여, 강수 확률을 보고 러닝 요일을 정하고 **야외 러닝 / 트레드밀**을 추천합니다.

※ 1~4번은 AI의 도움을 많이 받아 작성했다. 5번 코드 설명은 AI의 설명을 듣고 이해한 뒤 제 말로 고쳐 썼음을 밝힙니다.

## 1. 실행 방법 (uv)
```bash
git clone https://github.com/min90956/routine-maker.git
cd routine-maker
uv sync                       # Python 3.14 가상환경 생성 (외부 패키지 없음)
uv run smart_routine_maker.py # 프로그램 실행
```
- 필요한 것: [uv](https://docs.astral.sh/uv/), 인터넷 연결(날씨 기능 사용 시)
- 외부 라이브러리 없이 표준 라이브러리(`tkinter`, `urllib`, `json`)만 사용합니다.

## 2. API 키 / `.env` 설정
**Open-Meteo는 API 키가 필요 없습니다.** 따라서 제출할 키도 없습니다.
위치와 기준값만 `.env`로 바꿀 수 있고, `.env`가 없으면 기본값(서울, 60%)으로 동작합니다.

`.env.example`을 복사해 `.env`로 만들고 값을 바꾸면 됩니다. 형식은 `KEY=VALUE`, 한 줄에 하나입니다.
```
WEATHER_LOCATION_NAME=서울   # 결과에 표시할 지역 이름
WEATHER_LAT=37.5665          # 위도
WEATHER_LON=126.9780         # 경도
RAIN_THRESHOLD=60            # 이 강수 확률(%) 이상이면 트레드밀 추천
```
`.env`는 `.gitignore`에 등록되어 있어 저장소에 올라가지 않습니다.

## 3. 사용 방법
1. 운동 불가 요일 체크, 헬스/러닝 목표 횟수 입력, 지난주 부위별 강도 선택
2. **4. 다음 주 날씨 반영**(기본 켜짐) 확인 후 `★ 다음 주 루틴 자동 생성`
3. 결과 확인 후 `[저장 후 종료]` → `weekly_workout_routine.txt`로 저장되고 응원 메시지와 함께 종료

출력 예시 (러닝 날):
```
【 목요일 】 ★ [러닝]
  ☂ 날씨(11/12): 강수확률 5% · 강수량 0.0mm · 6~15°C
  ▶ 장소 추천: [야외] 맑음/흐림 → 야외 러닝 추천
```

## 4. 파일 구성

- 문서: `api-plan.md`(이번 기획안) · `plan-2.md`, `new_plan.md`(이전 기획안) · `CONVERSATION_*.md`(AI 대화 원문) · `.env.example`(설정 예시)

## 5. 코드가 어떻게 돌아가는지

`★ 다음 주 루틴 자동 생성` 버튼을 누르면 아래 순서로 진행된다.

**1. 입력값 모으기** (`smart_routine_maker.py` → `on_generate()`)
화면에서 운동 못 하는 요일, 헬스/러닝 목표 횟수, 지난주 부위별 강도, 날씨 체크 여부를 가져온다.

**2. 날씨 가져오기** (`weather.py`)
날씨 체크가 켜져 있으면 날씨부터 물어본다.
- `get_settings()` : `.env`에서 위치랑 기준 확률을 읽는다. 파일이 없으면 서울, 60%로 한다.
  > `.env`가 뭔지 정리 : 이번 과제를 하면서 처음 알게 됐다. `.env`는 프로그램 설정값을 `이름=값` 형태로 한 줄씩 적어두는 파일이다. 보통 API 키처럼 남에게 보여주면 안 되는 값을 코드에 직접 쓰지 않고 여기에 따로 둔다. 그래서 `.gitignore`에 넣어서 GitHub에는 안 올라가게 했다. 대신 어떤 형식으로 쓰는지 알 수 있게 예시 파일인 `.env.example`을 올려두었다. 내 프로그램은 키가 필요 없어서 `.env`에 지역(위도/경도)과 트레드밀 기준 확률만 넣게 했고, `.env`가 없어도 기본값으로 실행된다.
- `next_week_dates()` : 오늘 날짜로 다음 주 월요일을 찾고, 월~일 7일 날짜를 만든다.
- `fetch_weekly_weather()` : Open-Meteo 주소 뒤에 위도, 경도, 날짜를 붙여서 요청을 보낸다. 돌아온 답(JSON)에서 요일별 강수 확률, 강수량, 최저/최고 기온만 골라낸다.
  > API 요청이랑 JSON 정리 : API를 쓴다는 건 결국 정해진 인터넷 주소에 질문을 붙여서 보내는 것이었다. 예를 들면 `https://api.open-meteo.com/v1/forecast?latitude=37.56&longitude=126.97&start_date=...` 처럼 `?` 뒤에 `이름=값`을 `&`로 이어 붙이면 "이 위치, 이 날짜의 날씨를 알려줘"라는 뜻이 된다. 요청은 파이썬에 기본으로 들어 있는 `urllib`로 보냈다. 그러면 답이 JSON이라는 형식으로 오는데, JSON은 파이썬의 딕셔너리처럼 `"이름": 값` 모양으로 정리된 글자 데이터다. 답에는 정보가 많이 들어 있어서, `parse_daily()`에서 내가 필요한 강수 확률, 강수량, 최저/최고 기온만 요일별로 골라 정리했다.
- 인터넷이 끊겼거나 답이 이상하면 `WeatherError`를 낸다. 화면 쪽에서 이걸 잡아서 경고창만 띄우고 **날씨 없이 그냥 루틴을 만든다.** 그래서 프로그램이 꺼지지 않는다.

**3. 요일마다 운동 정하기** (`weather.arrange_slots()`)
러닝은 비 오면 못 하니까, 운동 가능한 요일을 **강수 확률이 낮은 순서로 줄 세운 다음** 앞에서부터 러닝 횟수만큼 러닝을 넣는다. 남은 요일에는 헬스(실내라 비와 상관없음)를 넣고, 그래도 남으면 휴식이다. ai가 방법을 잘 떠올린 부분이라고 생각한다. 
날씨를 안 쓰면 예전처럼 `default_slots()`가 헬스 → 러닝 → 휴식 순서로 번갈아 넣는다.

**4. 러닝 장소 추천** (`weather.run_advice()`)
러닝 날의 강수 확률을 보고 장소를 고른다.
- 60% 이상 → 트레드밀 (원래 추천 장소랑 대체 장소를 서로 바꿔서 보여줌)
- 30% 이상 → 야외로 가되 트레드밀도 생각해 두기
- 30% 미만 → 야외

러닝 횟수가 맑은 날보다 많으면 비 오는 날에도 러닝이 들어갈 수 있는데, 그때 이 규칙으로 트레드밀을 추천한다. 퍼센트는 내 기준에서 이정도면 이게 좋겠다 싶은 정도로 설정했다.

**5. 결과 글 만들기** (`routine_core.generate_routine_text()`)
이 부분은 지난 과제에서 만든 기능이고, 날씨 줄만 추가했다.
- 목표 횟수가 가능한 요일보다 많으면 비율에 맞게 줄인다.
- 지난주에 약하게 한 부위부터 배정하고, 강도에 따라 메인/보조 종목을 바꿔서 같은 운동만 반복하지 않게 했다.
- 운동마다 추천 기구와 대체 기구를 같이 적는다.

**6. 저장** (`save_and_exit()`)
결과를 `weekly_workout_routine.txt`로 저장하고 응원 메시지를 띄운 뒤 끝난다.

### 이렇게 만든 이유
- **키 없는 API를 고른 이유** : 마감이 얼마 안 남았기도 했고 날씨 관련 API 중 적절한 것을 발견했다. 특히 키 발급/활성화를 기다릴 시간이 없었다. 또한 키가 없으면 다른 사람도 `uv run`만 하면 똑같이 실행할 수 있다는 점도 이 방식을 선택하는데 영향을 줬다.
- **파일을 3개로 나눈 이유** : 기획안에 "200줄 넘으면 최대 3개로 나누기"를 정해 뒀는데, 날씨 기능을 넣으니 200줄을 넘었다. 그래서 화면 / 루틴 로직 / 날씨로 나눴다.
- **외부 라이브러리를 안 쓴 이유** : 표준 라이브러리(`urllib`, `json`)로도 충분해서, 설치할 것이 없게 했다.

## 6. 아쉬운 점
- 날씨 예보는 날짜가 멀수록 잘 안 맞아서, 다음 주 후반은 정확하지 않을 수 있다.
- 또한 온도가 너무 높거나 낮으면 실내운동을 권장한다던가 혹은 복장을 추천하는 기능도 넣었으면 더 좋았을 것 같다.
- 나처럼 우중 러닝을 즐기는 사람도 있다는 점이 살짝 걸린다.
- 위치는 `.env`에 위도/경도를 직접 넣어야 한다. 도시 이름으로 검색하는 기능은 없다.
